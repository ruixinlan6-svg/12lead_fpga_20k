# QN88 ECG：EC57 训练与正式验证数据库隔离方案

- 核查日期：2026-08-27
- 目标：为 QN88 上的“传统 QRS + 轻量 N/V 模型 + 十二导联融合”保留可审计、未被训练污染的正式验证证据
- 范围：只规划数据角色；本轮不下载数据、不训练、不改变现有 PTB-XL 或 FPGA 工程
- 证据：FDA 官方指南、PhysioNet/各数据库官方页面及其官方 WFDB header
- 限制：本文不虚构 FDA 最低样本量，也不替代授权版 ANSI/AAMI EC57:2012/(R)2020 的记录清单和排除规则

## 结论先行

1. **AHA、MIT-BIH Arrhythmia、MIT-BIH NST 默认全部锁定，不参加训练、阈值调节、量化校准或失败样本调试。** FDA 心律失常检测器指南建议至少使用两个数据库，并明确用于开发算法的数据库不应再用于测试和验证。[FDA Arrhythmia Detector and Alarm 指南](https://www.fda.gov/medical-devices/guidance-documents-medical-devices-and-radiation-emitting-products/arrhythmia-detector-and-alarm-class-ii-special-controls-guidance-document-industry-and-fda-staff)
2. **NST 不是独立患者外测。** 它的 ECG 是 MIT-BIH 记录 118 和 119 加入不同强度电极运动噪声得到的；如果使用 MIT 118/119 或 NST 调参，NST 的正式噪声压力测试资格同时被污染。[MIT-BIH NST 官方页](https://physionet.org/content/nstdb/1.0.0/)
3. **N/V(PVC/VEB) 轻量模型的首选开发库是 Icentia11k，而不是 MIT-BIH。** Icentia11k 有 11,000 名患者、约 27.74 亿个 `N/S/V/Q` 逐搏标注，足以按患者隔离训练和内部验证；但其许可是 CC BY-NC-SA 4.0，若研究模型未来进入商业/FDA 产品，必须在训练前取得明确许可结论或另行授权，不能把“公开可下载”理解为“可直接商业化”。[Icentia11k 官方页](https://physionet.org/content/icentia11k-continuous-ecg/1.0/)
4. **十二导联默认采用“训练与外测分开”的保守路线。** PTB-XL 用于十二导联记录级表征/五超类任务，LUDB 用于十二导联 QRS/波形边界开发，INCART 全库锁定为十二导联逐搏外测。PTB-XL 和 LUDB 都不能替代 N/V 逐搏标签。
5. **如果用 INCART 训练多导联 N/V 模型，就必须放弃其独立外测身份。** 此时要另找合法、受控、独立患者的十二导联逐搏数据；不能把 INCART 按患者切成 train/test 后再称“外部数据库验证”。
6. 后续扩展默认配对为：`Icentia S -> SVDB 外测`、`Icentia/LTAFDB -> AFDB 外测`、`VFDB -> CUDB 外测`、`LTSTDB -> European ST-T 外测`。一旦把右侧数据库用于调参，它就降级为开发/内部库。
7. **AHA 拿不到时只能诚实报告“MIT-BIH + NST 的公开子集 EC57-style 方法评测，未完成 AHA”。** INCART、Icentia 或 PTB-XL 不能静默替代 AHA，也不能宣称已完成完整 EC57 符合性验证。

## 1. 数据隔离的判定规则

### 1.1 三层角色

| 层级 | 允许用途 | 禁止用途 | 对外表述 |
|---|---|---|---|
| **D：development/train** | 训练、传统算法阈值、滤波/后处理设计、数据增强、QAT/PTQ 校准、超参数搜索、失败样本调试 | 不得再称独立验证 | 开发集/训练集结果 |
| **I：internal validation** | 模型选择、早停、阈值冻结、内部回归、同数据库患者留出 | 不得称外部验证；不得在正式测试后反复拿来补洞 | 患者隔离的内部验证 |
| **L：locked validation** | 模型、阈值、预处理、量化和 RTL 全部冻结后的一次性评测 | 不得参与训练、查看失败波形后改模型、PTQ 校准或板端调试 | 锁定数据库/外部或 EC57-style 验证 |

### 1.2 什么行为会污染锁定库

以下任一行为发生后，数据库角色必须从 `L` 降为 `D/I`，并在数据角色登记表记录日期、run_id 和原因：

- 用其任何信号、标注或统计量训练、自监督预训练、蒸馏或量化校准；
- 根据其总分、逐记录分数或失败波形修改滤波、阈值、refractory period、窗口、导联选择或模型结构；
- 把其片段加入单元测试、RTL golden、板端串口调试或演示回放；
- 在正式冻结前多次查看结果并选择表现最好的 checkpoint；
- 通过另一个聚合数据包间接使用同一记录。例如 PhysioNet/CinC Challenge 2020 训练数据包含 INCART 和 PTB-XL，若使用该聚合集，就不能继续把其中重复来源当作未见外测。[Challenge 2020 官方数据说明](https://physionet.org/content/challenge-2020/1.0.1/)

只读取数据库官方说明、建立版本/许可登记和校验公开 manifest 不属于算法开发；但运行算法并查看结果属于接触测试数据。

### 1.3 患者隔离优先于记录隔离

- Icentia11k 同一患者包含大量长片段，必须按 `patient_id` 切分，绝不随机打散 segment 或 beat；
- INCART 的 75 条记录只来自 32 个 Holter/患者，同一 patient number 的记录必须同层；
- PTB-XL 使用官方 `patient_id` 与 `strat_fold`，官方推荐 folds 1–8/9/10 分别作 train/validation/test；
- European ST-T、LTSTDB 等存在同一患者多条记录，必须按官方患者映射分组；
- 官方页面没有提供可靠患者映射时，不猜唯一患者数，先把整库保留为一个角色，或在取得 header/病例映射后再划分。

### 版本门禁

PTB-XL 旧版本常见数字是 21,837 条记录；当前官方 v1.0.3 在去除重复后为 21,799 条/18,869 人。已有本地数据可以继续使用其真实版本，但必须在 manifest 写明版本、记录数和 SHA-256，不能把 v1.0.1 的数据与 v1.0.3 的数量、fold 或哈希混写。

## 3. 按任务的数据库选择

### 3.1 传统 QRS 算法开发

**推荐：**

- `D`：LUDB 用于 12 导联 QRS 峰/起止和多形态开发；Icentia11k 患者子集用于长时 R-peak、运动噪声和宽泛患者分布开发；
- `I`：从 LUDB 与 Icentia 分别预先留出患者，评价 clean、多导联和长时单导联性能；
- `L`：MIT-BIH + AHA + NST。MIT/AHA 报 clean/主结果，NST 单独报各 SNR 退化；
- 噪声增强只从 `D` 层信号或独立采集噪声生成，不能复制 NST 的波形或在 NST 上寻找最优滤波参数。

LUDB 只有 10 秒，适合 delineation 但不足以证明长时心率/误报；Icentia 是单导联且标注由技术人员体系产生，适合大规模开发但不能取代锁定专家数据库。

### 3.2 N/V（PVC/VEB）轻量模型训练

**首选保守方案：**

```text
Icentia11k patient train
  -> Icentia11k disjoint-patient internal validation
  -> freeze model/preprocess/threshold/INT8
  -> MIT-BIH + AHA + NST locked bxb evaluation
  -> INCART locked 12-lead fusion evaluation
```

关键规则：

- `N/S/V/Q` 保持可追溯映射；当前二分类只取定义清楚的 N 与 V，S 和 Q 不得静默当作 N；
- 类别采样、患者采样和 hard-negative mining 仅在 Icentia train 患者内进行；
- Icentia internal validation 可以做模型选择，但报告时明确它是同数据库患者留出，不是外部验证；
- Icentia 的 NC-SA 许可是产品化硬门禁。若未取得商业许可结论，只能把该模型标记为研究候选；商业候选应改用拥有适当权利的受控数据重新训练并重新验证。

### 3.3 十二导联训练与多导联外测

默认采用 **方案 A：保留 INCART 外测**：

- PTB-XL folds 1–8：十二导联编码器、记录级 `NORM/MI/STTC/CD/HYP` 或自监督表征；
- PTB-XL fold 9：同任务内部验证；fold 10：同库锁定记录级测试；
- LUDB：十二导联 QRS/delineation、lead order、采样/尺度和跨导联时间一致性开发；
- Icentia：共享的单导联 N/V beat encoder；
- INCART：模型冻结后的完整 32-patient 十二导联逐搏外测，不参与任何训练/量化校准。

该方案更适合 QN88：训练一个小型单导联共享 beat encoder，再用确定性 lead-quality/late-fusion 组合十二导联；这样不需要消耗仅有的公开十二导联逐搏库来学习复杂 fusion。

只有当研究问题明确要求 learned multi-lead fusion 时才采用 **方案 B：消耗 INCART**：

1. 按 32 个 patient number 切分，绝不按 75 条片段随机切；
2. INCART 的任何留出只称 internal holdout；
3. 在训练前落实另一套受控、独立患者、12 标准导联、逐搏专家标注数据作为真正外测；
4. 若外部数据未落实，不开始 learned-fusion 训练，继续方案 A。

### 3.4 后续 SVEB/PAC

- `D/I`：Icentia11k 的 S/PAC beat，按患者训练/留出；
- `L`：SVDB 全库，报告 SVEB Se/+P、混淆和分记录结果；
- AHA 官方说明没有把 SVEB 与 normal 分开，不可作为 SVEB 唯一 gold；
- 如果 SVDB 被用于 hard-negative 或阈值调节，则必须降级，并寻找新的独立 SVEB 库。

### 3.5 后续 AF/AFL

- `D/I`：Icentia11k 的 AFIB/AFL rhythm + LTAFDB 按患者/记录来源隔离；
- `L`：AFDB，评价 episode/duration/burden；
- AFDB 的 `.qrs` 多为未人工纠正且所有 beat 都按 N，不能拿来训练 N/V 或宣称逐搏分类 gold；
- 如果目标是普通人群特异度，AF 富集库之外仍需目标场景独立非 AF 患者数据；本文不规定虚构样本量。

### 3.6 后续 VT/VF

- `D/I`：VFDB 的 rhythm-only episodes 用于事件模型开发；必要的逐搏 VEB 前端仍来自 Icentia；
- `L`：CUDB + AHA 中适用事件，报告 episode/duration、误报和延迟；
- CUDB 官方说明 onset 近似且 beat 全标 N，所以它只适合事件压力测试，不适合 VEB beat classifier；
- 22 条 VFDB 和 35 条 CUDB 都很小，百分比必须同时给原始事件数和观察时长。

### 3.7 后续 ST

- `D/I`：LTSTDB 按 80 个患者分组训练/内部验证；PTB-XL `STTC` 只能辅助 10 秒记录级表征；
- `L`：European ST-T 全库，按 79 个患者汇总 ST episode/measurement；
- 若把 European ST-T 用于调参，就不能再作为独立 ST 外测；
- MIT-BIH ST Change 官方资源目前没有 ST-change reference annotations，不纳入本方案的监督训练或 gold validation。

## 4. 可执行的三层数据方案

### Layer D：development/train

首轮 QN88 QRS+N/V：

| 数据 | 固定用途 | 分组键 |
|---|---|---|
| Icentia11k | QRS、N/V；未来 S/AF | `patient_id`；先固定患者列表，再抽 segment/beat |
| LUDB | 12 导联 QRS/delineation、lead order | 每名 volunteer/record |
| PTB-XL folds 1–8 | 十二导联记录级五超类/表征 | 官方 `patient_id/strat_fold` |

后续扩展才加入：LTAFDB（AF）、VFDB（VT/VF）、LTSTDB（ST）。不为未来任务提前打开其锁定对照库。

### Layer I：internal validation

- Icentia：在任何 beat/segment 抽样前冻结一组不进入训练的 patient IDs；
- LUDB：按 volunteer 留出，训练期不得查看其逐例结果；
- PTB-XL：使用官方 fold 9；
- 扩展库：LTAFDB、VFDB、LTSTDB 均按患者来源而不是窗口随机留出；
- 内部验证用于 checkpoint/阈值选择，因此它不是正式独立证据。

本文不指定 FDA 最低患者数，也不把 80/10/10 等经验比例写成法规门槛。执行 agent 应根据类别支持数、置信区间和训练预算预注册实际 patient IDs；样本不足时报告不确定性，不得靠把同一患者切成更多窗口增加“样本数”。

### Layer L：locked EC57-style / claim-specific validation

| 当前/未来声明 | 锁定数据库 | 开启条件 |
|---|---|---|
| QRS、N/V/PVC | MIT-BIH Arrhythmia + 正式 AHA + NST | FP32、量化、阈值、预处理、lead policy 和评测脚本哈希全部冻结 |
| 十二导联融合 | INCART（方案 A） | 软件/RTL/板端输出格式冻结；一次性按患者汇总 |
| SVEB/PAC | SVDB | S 类模型和阈值冻结 |
| AF/AFL | AFDB | episode 定义、最短时长、起止匹配冻结 |
| VT/VF | CUDB + AHA 适用记录 | 事件/报警定义与延迟规则冻结 |
| ST | European ST-T | ST 测量点、baseline 和 episode 规则冻结 |
| PTB-XL 五超类 | PTB-XL fold 10 | 仅是同库患者留出；不得称 EC57 或跨库外部验证 |

锁定评测第一次失败后，如果据此修改模型并再次运行，同一库虽然仍可报告为标准 benchmark，但“未见的一次性外部验证”资格已经丧失。必须保留所有尝试，而不是只保存最后一次。

## 5. AHA 无法取得时的诚实标记

建议报告标题固定为：

> **EC57-style public-subset evaluation on MIT-BIH Arrhythmia and MIT-BIH NST; formal AHA Database not evaluated.**

中文摘要固定说明：

> 本结果使用 WFDB/EC57 风格事件匹配与汇总方法，对 MIT-BIH Arrhythmia 和 MIT-BIH NST 进行评测。由于未取得正式 AHA Database 的合法副本，未完成 AHA 测试；PhysioNet 的 AHA excluded sample 不属于正式 AHA 数据库。本结果不宣称完成完整 EC57 符合性验证。

还必须：

- 在 manifest 中写 `aha_status: not_acquired`、核查日期、采购/联系状态；
- 不生成虚假的 AHA 空表、0 分或 `passed` 字段；
- 不把 INCART、Icentia、LUDB、PTB-XL 或 AHA excluded sample 改名为 AHA；
- MIT+NST 不应被宣传为两个独立患者来源，因为 NST 来自 MIT 118/119；
- 如计划用非 EC57 数据库替代，应在申报策略中说明来源、患者、标注和验证方式，并通过 predicate/Pre-Sub 确认，而不是在研发报告里自行宣布等价。

## 6. 执行前应冻结的产物

本文件只规划，不创建以下产物。执行 agent 在下载/训练前应建立：

1. `data_role_registry.csv`：`database/version/role/task/allowed_uses/prohibited_uses/license/owner/freeze_date`；
2. `splits/<database>_<version>.json`：明确 patient IDs、record IDs、分层规则和随机种子；
3. `dataset_manifest.json`：官方 URL、DOI、许可、记录数、患者数、导联、采样率、SHA-256；
4. `contamination_log.csv`：任何被打开评测、查看失败或误用于校准的锁定库；
5. `evaluation_freeze.yaml`：模型/阈值/预处理/量化/RTL/bitstream/评测器哈希；
6. `locked_run_receipt.json`：首次开启时间、运行人/agent、结果路径、是否导致后续模型修改；
7. 对应的 `docs/iterations/records/<run_id>.md` 与索引更新。

数据角色发生变化必须创建新记录，不能覆盖旧 manifest。任何 agent 在开始前先读取 `data_role_registry.csv`；不能因为文件已经在共享磁盘上就默认获准用于训练。

## 7. 不可越过的门禁

- 未完成 Icentia11k NC-SA 许可判断，不把其训练权重列为商业产品候选；
- 未冻结 patient IDs，不开始 segment/beat 抽样；
- 未落实独立十二导联外测，不用 INCART 训练 learned fusion；
- 不用 MIT-BIH、NST、AHA、SVDB、AFDB、CUDB、European ST-T 做 PTQ 校准或 FPGA golden 调试；
- 不把 PTB-XL 记录级 SCP 标签转换成未经标注的逐搏 N/V 标签；
- 不把 AFDB 自动 QRS 当作 VEB gold，也不把 CUDB 全 N beat label 当作真实逐搏类别；
- 不报告 FDA 最低样本量或统一分数线；本文和公开数据库页面都不能支持此类数字。
