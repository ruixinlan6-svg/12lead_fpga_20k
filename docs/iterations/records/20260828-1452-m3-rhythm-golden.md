## Optimization

- Method: implement a small stateful Python reference whose only time basis is a non-negative integer millisecond timestamp. An optional 250 Hz `sample_index` is used solely for exact stream-integrity checking; when supplied on consecutive stream observations it must increment by one.
- Why this method: integer milliseconds represent the explicitly requested 9.999/10.000 s, 4.999/5.000 s, and 2.999/3.000 s boundaries exactly without floating-point runtime comparisons, while the optional sample index independently verifies duplicate, missing, and out-of-order samples.
- Alternatives considered and why not selected: a sample-index-only clock cannot represent 9.999 s at 250 Hz; floating-point seconds would violate the integer-Golden constraint; deriving events from wall-clock time would be nondeterministic.
- Expected mechanism: timestamp differences drive hysteretic duration states and asystole; QRS beat labels drive ventricular and periodic-pattern states; every result separates one-shot `point_events` from durable `active_states` and includes ordered counters/status.

### Frozen interface semantics for this run

- `RhythmInput(timestamp_ms, valid_lead_count, hr_bpm=None, qrs_valid=False, beat_class=None, sample_index=None)` is one atomic observation. `timestamp_ms` is strictly increasing after the first accepted observation; all values are integers and booleans, never floats.
- `sample_index` may be omitted for event-level/specification vectors. When present, the first non-negative value establishes the stream origin; later supplied values must be exactly previous + 1. Duplicate, backward, and forward-gap observations emit no rhythm event, increment `DUPLICATE_SAMPLE`, `OUT_OF_ORDER_SAMPLE`, or `MISSING_SAMPLE`, and flush temporal/beat state. A forward gap adopts the received index as the recovery anchor; duplicate/backward input retains the prior anchor.
- Invalid fields, backward/equal timestamps, HR outside the frozen 30--220 bpm range, QRS with zero valid leads, or a beat label without a valid QRS fail closed as `INVALID_CONFIGURATION`/`OUT_OF_ORDER_SAMPLE`: no unqualified active/event output, no beat processing, and an auditable counter increment.
- `hr_bpm=None` means HR invalid and breaks pending HR assertion/clear timers. It does not clear an already active brady/tachy state; those states require their frozen valid-HR clear condition. Zero valid leads clears all rhythm/pattern state and exposes only `SIGNAL_LOSS`; reacquisition starts a new asystole interval.
- Brady/tachy timers start at the first observation satisfying the relevant strict threshold. The assertion is visible at elapsed 10,000 ms and clearing at elapsed 5,000 ms. Values in the hysteresis bands neither assert nor clear.
- With at least one valid lead and no prior QRS, the asystole clock starts at the first valid-lead observation. Assertion is visible at elapsed 3,000 ms; the next valid QRS clears it.
- `beat_class` is `"nonV"`, `"V"`, or absent. It is legal only with `qrs_valid=True`; an absent class on a QRS is treated as an unclassified beat that breaks a ventricular run and may violate a periodic pattern.
- `PVC_COUPLET` is a point event only on the second consecutive V. A third V activates `VENTRICULAR_RUN`; the next non-V/unclassified beat clears it. `VT_CANDIDATE` is active when a run has at least three V and the exact median V--V interval is no more than 600 ms. For an even interval count, comparison uses the rational middle-pair sum, so exactly 600 ms (100 bpm) passes without division.
- Bigeminy/trigeminy activate when the suffix first equals the frozen 6-/9-beat pattern. After activation their phase remains locked to the repeated pattern; every subsequent beat advances the phase, a correct beat resets the violation counter, and the second consecutive mismatch clears. Assertion is exposed once in `point_events`; clearing is represented by disappearance from `active_states`, avoiding an unfrozen new event name.
- Point-event and active-state tuples use a fixed declared order. Reset clears temporal and beat state, preserves auditable cumulative error counts, increments `RESET_SEEN`, and makes replay from the reset boundary deterministic.
